# ReneStore

ReneStore is an e-commerce application with a React/Tailwind frontend, an Express API, Drizzle ORM, and PostgreSQL. Its admin analytics dashboard presents descriptive, predictive, and prescriptive analyses.

## Setup

### Requirements

- Node.js and npm
- PostgreSQL database
- Environment variables configured locally; never commit `.env` files or credentials

### Install

From the repository root:

```powershell
cd Backend
npm install
cd ..\Frontend
npm install
```

### Configure

Create `Backend/.env` and set at least `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, `CLIENT_URL`, and any API keys required by enabled integrations. Use [`Backend/.env.example`](Backend/.env.example) as the variable-name reference. Keep values private.

Create `Frontend/.env` using [`Frontend/.env.example`](Frontend/.env.example) as a reference. For local development, set `VITE_API_URL` to the backend API URL and keep `VITE_USE_MOCK=false` to use the database-backed API.

### Apply schema and import verified data

Back up the database before applying migrations. Applying migrations changes the database schema.

```powershell
cd Backend
npm run db:migrate
```

To import genuine records, copy the relevant header-only files from `Backend/data/templates/` into `Backend/data/import/`, fill them with authorized, source-verified records, then run:

```powershell
npm run import:data
```

The importer validates required fields, types, dates, duplicate products, and foreign keys. It does not truncate or overwrite existing records. Product IDs are generated by PostgreSQL; the product CSV includes supplier names and image URLs, and suppliers are created when needed. The importer also accepts the legacy product header with explicit IDs and supplier IDs. Resolve validation errors from the report before relying on imported analytics.

Run the app in two terminals:

```powershell
# Terminal 1
cd Backend
npm run dev
```

```powershell
# Terminal 2
cd Frontend
npm run dev
```

Open the frontend URL printed by Vite. Sign in with an existing authorized administrator account; the project does not publish default credentials.

## Dashboard guide

- **Descriptive:** order KPIs, monthly revenue/profit, product/category and customer summaries, campaign metrics, inventory purchases, and descriptive statistics.
- **Predictive:** linear regression and 3-month moving average, selectable forecast horizon, model-fit statistics, campaign ROI estimates, and product stockout risk.
- **Prescriptive:** linear-programming budget scenario with configurable bounds and an inventory reorder plan. Estimates depend on observed campaign records, the chosen constraints, and inventory history.
- **Case Study:** problem statement, live database statistics, editable data-source notes, and print-to-PDF through the browser.
- **Process Flow:** API-derived outputs connected from descriptive through predictive and prescriptive steps to a decision summary.

## Five-minute capstone demo

1. **0:00–0:40 — Background:** introduce ReneStore and the business question in the Case Study tab. Explain that all findings are conditional on verified source data.
2. **0:40–1:20 — Data overview:** show table counts and documented sources. State which tables meet the record threshold and distinguish row counts from provenance verification.
3. **1:20–2:10 — Descriptive:** demonstrate a date/category/channel/city filter, inspect a chart and KPI, and export a table as CSV.
4. **2:10–3:00 — Predictive:** choose a 3-, 6-, or 12-month horizon, compare regression with the moving average, and explain R² and RMSE. Point out any limited-data warning.
5. **3:00–4:10 — Prescriptive:** adjust a budget or channel limit, run optimization, and review the allocation chart, estimated returns, action list, and reorder plan.
6. **4:10–5:00 — Process flow and limitations:** trace outputs across the four cards, then summarize data-provenance, record-volume, and model-fit limitations.

### Likely panel questions

- **Why linear regression?** It provides a simple, explainable trend baseline. The moving average is shown as a comparison; neither model captures every seasonal or external factor.
- **What does R² mean?** It describes the proportion of historical variation explained by the fitted linear trend. A low value means the trend is a weak fit, not that the forecast is a guarantee.
- **How does the budget optimization work?** It maximizes estimated campaign profit from recent observed campaign ROI subject to the total budget and per-channel minimum/maximum bounds. The output is a scenario, not a promise of future performance.
- **Where did the data come from?** Name the verified system/source recorded for each table in the Case Study. If a source has not been verified, say so and do not present those records as real.
- **What are the limitations?** Data provenance and sample size, incomplete periods, historical ROI stability, and unmodeled external factors can all affect the recommendations.
